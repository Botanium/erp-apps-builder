# Owner Interview and Blueprint review prototype

Three structurally different interaction models for the Owner Interview and
Blueprint review, switchable through `?variant=A`, `?variant=B`, and
`?variant=C` on one disposable local route.

Question: which model makes Intent State, source, Sensitive Data Class,
Assumptions, exclusions, Semantic Diff, Approval Eligibility, and explicit
Blueprint Approval understandable without implying that preview or selection
is approval?

Run with one command:

```sh
npm run prototype
```

Open `http://127.0.0.1:4173/?variant=A`.

This is a non-authoritative UI prototype. All content and actions are
fictitious local stubs. It performs no Business Kernel action.
